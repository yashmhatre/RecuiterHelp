# P1-02: Resume file parsing to clean text

**Phase:** 1 · **Est:** 1 day · **Blocked by:** nothing

## Owns
- `profiles/parse_resume.py`
- `tests/test_parse_resume.py`
- `tests/fixtures/resumes/` (synthetic files, safe to commit)

## Reads
- nothing — pure function, `bytes`/path in, text out

## Context
A self-contained text extractor. Keeping it separate from profile extraction means the model
step can be retuned without touching file handling, and bad PDFs get diagnosed in one place.

## Scope
**Do**
- `parse(path) -> ParsedResume` with `text`, `page_count`, `warnings`.
- Support PDF via `pypdf` and DOCX via `python-docx`.
- Normalise: collapse runs of whitespace, join words broken across line ends, strip repeated
  headers and footers, preserve section order and bullet boundaries.
- Handle and report clearly, never crash: encrypted PDF, scanned/image-only PDF (near-zero text
  → warning `no_extractable_text`), `.doc` legacy format (unsupported, named as such),
  zero-byte file, wrong extension for the real content.
- Deterministic output: the same file always yields identical text.

**Do not**
- Call a model, touch the database, or add OCR. Flag image-only PDFs for manual handling.

## Independence
Ship synthetic fixtures generated by a committed script (`tests/fixtures/make_fixtures.py`) using
`reportlab` and `python-docx`. **No real candidate resumes in the repo** — that is the data-exposure
risk in the plan.

## Acceptance criteria
- [ ] Text extracted from a multi-page PDF and a DOCX with tables and bullets
- [ ] An image-only PDF returns `warnings=["no_extractable_text"]` and does not raise
- [ ] An encrypted PDF and a `.doc` file each return a named warning and do not raise
- [ ] Words hyphenated across a line break are rejoined
- [ ] Two runs on the same file produce byte-identical text
- [ ] No real resume is committed

## Done when
`pytest tests/test_parse_resume.py` passes with only the synthetic fixtures.
